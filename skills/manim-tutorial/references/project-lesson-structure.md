# Project and lesson structure

Inspect existing project names, READMEs, lessons, and reusable assets before proposing placement.

Use an existing project when the requested concept is a natural part of that subject and shares its prerequisites, vocabulary, or visual language. Create a new project when the concept forms an independent field, needs its own prerequisite sequence, or has no coherent existing home. Avoid catch-all projects.

Split a topic whenever it contains multiple independently teachable insights. Make each lesson understandable as one step in an ordered sequence rather than one chapter of an oversized video. Keep the project README as the ordered syllabus, including each lesson's central insight and any prerequisite lesson.

Before creating or modifying tutorial files for a new project or multi-lesson request, present this briefing and wait for approval:

```text
Goal and audience
State what the learner should understand and assumed prerequisites.

Placement
Name the existing or new project and explain why it is the coherent home.

Lesson sequence
For each proposed filename, state its central insight, prerequisite, and main visual idea.

Shared material
List reusable assets, diagrams, notation, or scene motifs.

Boundaries
State what is intentionally out of scope or deferred.

Files
List the project README, lesson files, and assets to create or update.
```

Treat a broad field such as agentic reinforcement learning as a new project with a prerequisite-ordered series. Treat a narrower extension such as diagonalization as multiple lessons within linear algebra when the existing project supplies the right foundation.

Do not scaffold directories, author lessons, or render while the briefing awaits approval. Read-only inspection is allowed. If the user revises the scope, update the briefing before implementation.
